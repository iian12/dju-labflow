# ADMIN API 테스트

## 진입과 권한

Studio의 ADMIN 계정으로 로그인하면 상단에 **API 테스트** 링크가 표시됩니다. 주소는 `http://127.0.0.1:5181/#/api-test`이며, `/#/api-test/run-metrics`처럼 API별 직접 링크도 지원합니다.

`GET /api/v1/auth/me`는 현재 DB의 `role`을 함께 반환합니다. 도구 진입 시, 15초마다, 각 테스트 요청 전후에 `GET /api/v1/admin/api-test`로 권한을 확인합니다. 서버는 ADMIN만 허용하며 비로그인은 401, USER는 403입니다. 이전 ADMIN JWT라도 DB에서 역할을 회수하거나 계정을 차단하면 다음 검사에서 거부됩니다. 도구는 권한 확인 실패 시 폼·키·기록을 제거합니다. 일반 API의 소유권 및 공개 정책은 그대로 적용되며, 관리자가 다른 사용자의 PRIVATE 프로젝트에 접근하는 기능을 추가하지 않습니다.

회원가입은 기존처럼 USER 계정만 생성합니다. 테스트 도구를 통한 관리자 승격이나 기본 관리자 비밀번호는 제공하지 않습니다.

## 요청 구성

- 회원·인증, 프로젝트, API 키, 실험 실행, 조회·비교, 파일의 6개 그룹에서 현재 구현된 39개 API를 선택합니다.
- Project/Run/Key/Artifact ID와 프로젝트 Version을 연결 컨텍스트에 입력합니다. 생성·상세 조회 응답에서 다음 요청의 식별자를 자동으로 채웁니다.
- JSON 폼과 원본 JSON 편집을 지원하며 64비트 ID·Step의 자릿수를 보존합니다.
- 쿠키 요청의 CSRF를 자동 준비하고, 테스트 요청에 쿠키 또는 CSRF를 제외해 실패 응답도 확인할 수 있습니다. 관리자 권한 확인 요청에는 이 옵션을 적용하지 않습니다.
- SDK 요청은 쿠키 없이 Bearer 키를 사용합니다. SDK 쓰기에는 선택적인 Request ID를 지정할 수 있고 파일 업로드에는 비어 있으면 자동 생성합니다. 같은 요청 ID로 다른 내용을 보내면 서버가 충돌로 거부할 수 있습니다.
- 파일 업로드는 실제 바이너리 본문을 사용합니다. 다운로드는 응답 상태와 파일 크기를 기록하고 파일을 저장합니다.
- 성공·실패 상태, 소요 시간, 응답과 전송 본문을 확인하고 최근 40개 요청을 메모리에 보관합니다. 비밀번호·키·인증 코드는 기록에서 마스킹하며 localStorage에 저장하지 않습니다.
- 테스트 응답의 401이나 네트워크 실패를 자동 재시도하지 않습니다. 도구의 ADMIN 세션 확인은 별도로 공통 세션 갱신 정책을 사용합니다. 로그인·로그아웃 테스트로 현재 사용자가 ADMIN이 아니게 되면 도구가 닫힙니다.

서버의 실제 컨트롤러 매핑을 ADMIN API가 반환하므로 프런트 폼에 없는 새 API를 화면에서 알려 줍니다. 자동 검사도 카탈로그와 컨트롤러의 일치를 확인합니다. 이전 별도 디자인 앱과 해당 앱 전용 브라우저 통합 테스트는 제거하고 현재 Studio의 테스트로 대체했습니다.

## 검증

프런트 폴더에서 `npm run build`, `npm test`를 실행합니다. 모의 API 브라우저 검사는 ADMIN/USER/비로그인 진입, 권한 회수 후 요청 차단, 큰 정수, 비밀값 마스킹, 모바일과 테마를 확인합니다. 요청 클라이언트 검사는 쿠키/CSRF/Bearer 분리와 파일 전송·커서를 확인합니다.

실제 HTTP/H2 서버와 브라우저를 연결하는 통합 검사는 저장소 루트 PowerShell에서 실행합니다.

```powershell
$env:LABFLOW_ADMIN_NODE = (Get-Command node).Source
.\backend\gradlew.bat -p backend test --tests com.dju.labflow.AdminApiBrowserIntegrationTests --no-daemon
```

Java 21과 프런트 의존성, 설치된 Edge가 필요합니다. 테스트는 임시 ADMIN과 PRIVATE 프로젝트로 로그인, API 목록 일치, 키·Run 생성, 지표·Heartbeat, 바이너리 업로드·다운로드, 로그아웃 후 도구 제거를 검증합니다. 임시 데이터를 정리하며 운영 DB나 SMTP를 사용하지 않습니다. 결과 로그는 무시된 `backend/build/admin-api-browser.log`에 남습니다.

`AdminApiHttpTests`는 별도 환경변수 없이 ADMIN/USER/비로그인/Bearer만 전송한 요청, 역할 회수, 차단 계정, 최신 세션 역할과 no-store 응답을 검증합니다.

최종 검증(2026-11-20): 백엔드 전체 빌드·Spotless 및 263개 테스트가 건너뜀 없이 통과했습니다. ADMIN·Studio·기록 커서의 실제 브라우저 통합과 Python SDK·실제 모델 학습 통합을 모두 활성화했습니다. 프런트 빌드와 29개 테스트, SDK 단독 128개 테스트와 Ruff lint/format도 통과했습니다. SDK 단독 실행에서 건너뛴 외부 연결 6개는 백엔드의 Python 통합 경로에서 실행했습니다.
